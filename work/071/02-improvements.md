## Holes to watch out for (summary)
- **Stale line 2 (002/011).** A line-2-only reader misreports a stale summary. Cross-check with the last I3 log line from ID 41, and report a disagreement as INCOMPLETE, never as a guess.
- **Regex shapes.** Allow `**` bold. Take the first word only (a FAIL inside parentheses is not FAIL). Reject the unfilled `PASS | FAIL`. Anchor with `^`/`re.M`, so a mid-line `Verdict:` is not read. Decide on case (`.upper()` as in 042, or strict). Decide whether a `Verdict:` inside a ``` fence counts. Each needs a negative test (i3-verifier.md:14, RI-012).
- **Precedence.** 06 FAIL must beat an older 07 A1 FAIL (069/070 order). Without a fixture for it, the current code order prints `A1 FAIL` (01 F28).
- **Self-reference.** In round 2, I3's own pasted `check_pipeline line:` and the repo test will show this item's `I3 FAIL`. The agent text must say that is expected, or I3 will FAIL its own re-verification on it.
- **Parallel items.** With exit 1, every other item's I3 on the same branch sees red during the send-back window and must record it as not its defect.
- **No Verdict line.** The fixture helper writes 06 with no Verdict line (tests/test_pipeline_check.py:19-34). Treat a missing or unreadable verdict as INCOMPLETE only from a cutoff ID (071), and as not checked below it. Never treat it as PASS from the cutoff on (RI-002). Otherwise most existing fixtures go red.
- **Send-back target.** Read it only from a closed-vocabulary `Sent back to:` field. Below the cutoff, print "not stated". Never default to I2 (RI-002). A FAIL can go to both I1 and I2 (062).
- **Open branches.** `open_branches()` reports only `SKIPPED` (check_pipeline.py:838-840), so a branch's A1 FAIL or I3 FAIL is invisible on main. Either add a `BRANCH I3 FAIL:` line or name the gap in the docstring. R2 leans to naming the gap and leaving it out of scope, because 042 left A1 FAIL out the same way.
- **IN PR tuple.** Add `I3 FAIL` to the tuple at L796, or a fixed item waiting on a PR shows as `I3 FAIL` on main.
- **Log ordering.** Lines written after UTC midnight land in the next day's file (070, 11-18 00:00). Sort by file date, then line order, and never by HH:MM alone.
- **Agent text.** i3 step 5 says "On PASS, write 06". Change it in this item, or the check rests on a practice the rules contradict (01 F26).
