**Changes from the 03 map. These are the reasons for "WITH CHANGES".**
1. **Package name `ccbot/`, not `covercalls/`.** It is shorter, and there is one CLI: `python -m ccbot backtest|scan|report` (plus `make-sample`). This replaces the separate `python -m covercalls.bot` entry point.
2. **Calibration (`calibrate.py`, 03 step 15) is deferred.** No real snapshots exist yet. The snapshot log is still written, so calibration can be added later. Reports say "k UNCALIBRATED".
3. **The delta band needs a tolerance, or it often has no strike** (new edge case, see research 1). On a $0.50 grid near $24 with 30–45 DTE, delta moves about 0.09 per strike, which is wider than the 0.05-wide 0.25–0.30 band. Rule: pick the grid strike whose delta is **nearest 0.275**. Trade it if its delta is in **[0.20, 0.35]**, and log `in_band = 0.25 ≤ Δ ≤ 0.30`. Otherwise no trade, `reason=NO_STRIKE_IN_TOLERANCE`. The same rule applies in the screen and the bot.
4. **The cost-basis rule needs a defined result.** If the chosen call strike < cost basis, move up to the lowest grid strike ≥ basis. If that strike's delta < 0.20, do not sell, and log `reason=BASIS_ABOVE_BAND` (001 step 9b).
5. **Two synthetic underlyings, not one.** `SYNTH_A` is an ETF (`asset_type: "etf"`, no earnings, quarterly dividends, starting at $24), so the shipped config passes the screen at $3k. `SYNTH_B` is a stock (`asset_type: "stock"`, earnings flags, starting at $14, 1 year) for the earnings-blackout and 50%-cap tests. With one "stock" sample carrying earnings, the 50% cap would fail at $3k ($2,400 > $1,500), so the shipped-config test could never pass.
6. **The generator uses stdlib `random.Random(42)`**, not numpy. That keeps the "byte-identical regeneration" test true across numpy versions.
7. **Paper logs go in `state/`** (`state/sim_ledger.json`, `state/paper_trades.csv`, `state/paper_snapshots.csv`), not `logs/paper/`. `logs/` holds the agent team logs that A1 reviews. One ignored folder keeps bot data separate.
8. **Webull SDK guard order** (new, see research 2): constructing `TradeClient`/`DataClient` makes a network call at once. So the adapter must create `ApiClient`, call `add_endpoint`, and assert the resolved host **before** it constructs either client. It must also not let the SDK write its default `webull_*_sdk.log` or `conf/token.txt` into the repo.
9. **The walk-forward selection basis is stated.** Selection uses calendar-year returns from each config's full-period run, restricted to the train years. This is an approximation; runs are path-dependent. The report says so.

## Extra research (with sources)

1. **Delta per $0.50 strike vs. the 0.05 band.** Black-Scholes call delta is N(d1). Its sensitivity to strike is about φ(d1)/(Kσ√T). At S=K≈$24, σ=0.25, T=35/365 (σ√T≈0.077), φ≈0.39: 0.39/(24·0.077) ≈ 0.21 per $1, or about 0.10 per $0.50 step. So a 0.25–0.30 band (width 0.05) often contains no listed strike. Source: standard BS delta (macroption BS formulas page, cited in 03 B9) plus this arithmetic. That is why change 3 adds a tolerance.
2. **Official SDK, read from the wheel** (`pip download webull-openapi-python-sdk==3.0.4 --no-deps`, unzipped and read, not installed or run). These are the facts the adapter depends on:
   - Imports: `from webull.core.client import ApiClient`, `from webull.trade.trade_client import TradeClient`, `from webull.data.data_client import DataClient`, `from webull.core.endpoint.resolver_endpoint_request import ResolveEndpointRequest`.
   - `ApiClient(app_key, app_secret, region_id)`. `add_endpoint(region_id, endpoint, api_type="api")`. Endpoint types are `"api"` (HTTP trading **and** HTTP market data) and `"quotes-api"` (used only by the streaming `webull/data/internal/quotes_client.py`).
   - The default `us` map is `api.webull.com`, `data-api.webull.com`, `events-api.webull.com` (`webull/core/data/endpoints.json`), all **production**.
   - `TradeClient(api_client)` and `DataClient(api_client)` call `ClientInitializer.initializer` → `ConfigOperation.get_config()` (an HTTP call) and the token init when they are constructed. They also add stdout logging plus a log file `webull_trade_sdk.log` / `webull_data_sdk.log` in the CWD, unless a logger is already set. The token is stored at `conf/token.txt` in the CWD unless `set_token_dir` or env `WEBULL_OPENAPI_TOKEN_DIR` is set.

The payload shape follows `samples/order/order_option_client.py`: `client_order_id, combo_type="NORMAL", order_type="LIMIT", quantity, limit_price, option_strategy="SINGLE", side, time_in_force, entrust_type="QTY", legs=[{side, quantity, symbol, strike_price, option_expire_date, instrument_type="OPTION", option_type, market="US"}]`.
