## Extra research (with sources)
1. Python `ast` docs (https://docs.python.org/3/library/ast.html, fetched 2026-11-25). `ast.Compare(left, ops, comparators)` is "A comparison of two or more values". `ast.walk` yields descendants "in no specified order". Effect on the plan: the census compares `collections.Counter`s, never ordered lists, so walk order cannot matter. A chained or nested Compare (`a < X_FROM < b`, or `(i < X_FROM) == y`) is one or two nodes. Today none exists (03: 18 Compare nodes hold a `*_FROM` Name, 17 after dropping `_note`'s `cutoff != UNTRACKED_FROM`). If one is added, the census mismatch makes the builder look at it, which is the purpose.
2. The census must stay green under the FROM-1 mutants (`>= NAME - 1`). In those, the Name sits inside a BinOp comparator, not as a direct operand. So the census must take Names from `ast.walk(compare)` (as 03 says), not only from `left` / `comparators` themselves. A direct-operand census would fail under all 17 FROM-1 mutants and would wrongly "take the kill". This is pinned by step 8's rule that `test_from_site_census` is never in a mutant's failing ids.
3. Equivalence check of S7 FROM-1 (re-traced from `incomplete`, the TIMED gate branch keyed on `TIMED_FROM`). At 089, `log_fields_ok(..., timed=True)` and `timed=False` apply the same LOG_FORMAT (`timed` only matters for IDs >= TIMED_FROM). So `"I2" in bad` means some own I2 line fails, `all(... timed=False)` is False, and the branch is never entered. So the mutant is equivalent, as 03 says. S8 FROM-1 is not equivalent: the branch keyed on `TESTS_FORMAT_FROM` calls `_rule_seen`, and with no RULE_FILE in the anchor tree `_rule_seen` returns `(None, "05 anchor <sha7> has no scripts/check_pipeline.py (item 084)")`, which is appended as `note`. Confirmed in `_rule_seen` (the `if not ls.strip()` branch).
4. Mutation-testing terms (operator vs boundary mutants) as 03 corrected them: https://pytest-gremlins.readthedocs.io/en/latest/guide/operators/ (03 fact-check row, fetched 2026-11-25). Nothing new.
