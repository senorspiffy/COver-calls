3. **Close F-2 and F-4 with the FOR 1 check plus one piece of state, not a full indent model. ## Holes to watch out for (summary)
1. **The value check must run only on plain text** (FOR 1). It must skip quoted values (p9), flow values (q23 `args: [...]`), FLOW_KEYS lines and block content. 2. **`name: x:` (end-of-line colon)**: sources disagree (AGAINST 1). Probe it in PyYAML before pinning it as "invalid". A fail-closed error is acceptable either way, if it is documented.
3. **Block header grammar** (FOR 2): accept `|`, `>`, `|-`, `>+`, `|2`, `|2-`, `|-2` and a trailing ` # c`. Content ends at the first non-blank line indented no more than the key. Blank lines inside the block are content. `description: |` with no indented line after it is an empty block. R2 did not fetch spec 8.1.1, so the order of digit and chomping indicator is UNVERIFIED.
4. **One helper for "rest empty or only a comment"** (FOR 3, F-5): use it in `prev_open` and in the indented parent state, so M61 kills both F-5 fixtures and an indented case. Do not change `_field`'s `tools: # c` / `- Read` behaviour silently. R1 OQ4 is R3's call. If it is left alone, add it to the docstring's known false errors next to F-5's removal.
5. **Overlapping mutations**: FOR 1 and FOR 3 share the value check, so M56 and M58 may be equivalent. Give each mutation a fixture only it kills (for example, `hooks:` / `  a: b: c` for the key-with-value path and `name: x` / `  foo: bar` for the continuation path).
