## 3 ways AGAINST
1. **The non-merge walk has its own blind spots.** (a) A trigger change made only while resolving a merge conflict is in no non-merge commit, so it is never seen. This is 053's gap (d) inverted: 053 sees it inside the merge, and 070 would not. (b) A change that is committed and later reverted still triggers, which forces a 22-minute realtest run for a net-zero diff. (c) A squash or rebase merge drops the item's commits. 053 already fails then, with `cutoff not in HEAD's history`. Mitigation: name (a)-(c) as known gaps in the docstring, as 053 does. For (b), the person can accept the `not required (...)` text only via a named exception set, like LOG_TIME_EXCEPT. Not needed today.
2. **A TOTAL line proves that something was pasted, not that the paste is right or current.** If 06 copies 05's TOTAL line, it passes. A TOTAL line pasted in build round 1 still passes after a round-2 commit changes realtest.py again. The template asks for before/after SHAs (build-report.md:10), but the check does not read them. This risks false assurance on exactly the numbers RI-013 is about. Mitigation, two options: (i) also require a line naming an "after" SHA equal to or later than the item's last trigger commit. That is stricter and needs a fixed format the template doesn't define yet. (ii) Leave it at TOTAL presence and state in the docstring that I3 still compares 05 and 06 (verification.md:7). R3 should pick one. R2 leans to (ii) now and (i) as a follow-up, so the template format is not changed in the same item.
3. **Cost and complexity on a RULES BRANCH.** check_pipeline.py already has 565+ lines before main() and about 12 report kinds (docstring L20-110). This adds a third git walk (rev-list plus one diff-tree per commit after UNTRACKED_FROM). Its runtime is UNVERIFIED: R2 had no shell and the commit count after 694bf4d was not measured. Caching diff-tree results shared with `_walk` would avoid paying twice for first-parent commits. The person must OK the PR (01 F23), and it stacks on the still-open PR #30, so 070 cannot merge before #30. There is also a lighter alternative: one line in i2-builder/i3-verifier plus the 06 checklist. But that is the text-only duty RI-010 says fails, so the check is still worth it. The cost is the reason to keep it small.

## Holes to watch out for (summary)
- Searching the whole file for TOTAL accepts an empty section (067/05 has TOTAL at L116 in Test output). Read the section only, and handle fences and comments.
- Using first-parent units on main gives false positives for multi-item PRs, and that is the usual case per the audits. Walk non-merge commits and prove it with fixture 6.
- Conflict-only trigger edits and squash merges are invisible to a non-merge walk. Document them as known gaps.
- A copied or stale TOTAL line passes. The check proves a paste, not freshness. Say so in the docstring, and I3's 05/06 comparison stays a duty.
- Trigger drift: a new ccbot import or `"config"/name` read in realtest.py. Use the ast test, and keep one source of truth (TRIGGER constant, template comment pointing to it). Dynamically built paths escape the ast test (UNVERIFIED whether any exist today; 01 F9 found only literal names).
- data/real/ is tracked in git, so leaving it out (04's shortened list) misses data refetches that change realtest output.
- No git must give "not checked", never INCOMPLETE. Otherwise the `x\n` fixtures in tests/test_pipeline_check.py break (01 F20).
