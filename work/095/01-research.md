## Findings (one claim per line, each with [source URL] or UNVERIFIED)
### Git behaviour (shared by A and B)
- G1. The shallow file "lists commit object names and tells Git to pretend as if they are root commits (e.g. "git log" traversal stops after showing them ...)". "Shallow commits do have parents, but not in the shallow repo, and therefore grafts are introduced pretending that these commits have no parents." [https://git-scm.com/docs/shallow]
- G2. `git clone --depth=<depth>`: "Create a shallow clone with a history truncated to the specified number of commits. Implies `--single-branch` unless `--no-single-branch` is given to fetch the histories near the tips of all branches." [https://git-scm.com/docs/git-clone]. So case (B) arises only in a `--no-single-branch` (or later widened) shallow clone. A plain `--depth 1` clone lists no other refs; that is item 094's case (single-branch), not this one.
- G3. `git branch --no-merged [<commit>]`: "Only list branches whose tips are not reachable from <commit> (`HEAD` if not specified)." [https://git-scm.com/docs/git-branch]. In the shallow view HEAD's history stops at the boundary (G1), so the tip of a ref merged long ago is not reachable from HEAD and the ref is listed as not merged. This is derived from G1 + G3. A1 observed it: the full clone lists 1 ref, d1 lists 28, "all of them already merged into main" (logs/audit/2026-11-22-090.md L74-75).
- G4. `git merge-base --all`: "Output all merge bases for the commits, instead of just one." `--is-ancestor`: "exit with status 0 if true, or with status 1 if not. Errors are signaled by a non-zero status that is not 1." The page says nothing about the exit status when there is no common ancestor, and it does not mention shallow repositories [https://git-scm.com/docs/git-merge-base]. Exit 1 with no output for "no merge base" is A1's observation (git 2.43, logs/audit/2026-11-21-081.md L10; 090/01 B10): UNVERIFIED from the docs.
- G5. Direction (090/01 B2, derived from G1): the shallow view only removes parent edges. A merge base found in the shallow view is a real common ancestor, but "no merge base" (exit 1) is uncertain. A ref with no merge base in a shallow clone may be (i) merged into main, (ii) open and branched before the boundary, or (iii) truly unrelated (an orphan docs branch). Nothing in git's shallow view tells these apart. [https://git-scm.com/docs/shallow; derived]
- G6. `git fetch --unshallow`: "If the source repository is complete, convert a shallow repository to a complete one ...". "If the source repository is shallow, fetch as much as possible so that the current repository has the same history as the source repository." [https://git-scm.com/docs/git-fetch]. So "stays shallow" is a real end state (the source is itself shallow), and the not-checked text must stand on its own.
- G7. `--is-shallow-repository`: "When the repository is shallow print "true", otherwise "false"." [https://git-scm.com/docs/git-rev-parse]
- G8. In git log's history-simplification text, "Initial commits are compared to an empty tree" and "Root commits are compared to an empty tree" [https://git-scm.com/docs/git-log]. With G1 (shallow commits act as roots), `git log --diff-filter=A -1 -- <file>` in a depth-1 clone would name the boundary commit as the commit that added every file. The anchor (084) would then be the current tree, so every rule would read as "seen" and the old-rule excuse would never apply. Derived; UNVERIFIED by probe. This is why `_rule_seen` must not run in a shallow clone (A2), and why "keep strict" was chosen in 084.
- G9. Possible later CI: the GitHub actions/checkout default is `fetch-depth` "Default: 1", and "Only a single commit is fetched by default, for the ref/SHA that triggered the workflow"; "0 indicates all history for all branches and tags" [https://github.com/actions/checkout]. CI is not in the repo today (RI-010 L123: "CI left out by R2/R3"). If it is ever added, a depth-1 checkout is the default case, so the shallow output is not only a hand-run edge case.

### (B) Merged branches in a shallow clone
- B1. `open_branches` lists refs from `git branch -r --no-merged HEAD` (L1425). In a shallow clone it skips only origin/main (L1437-1438). [repo L1444-1457]
