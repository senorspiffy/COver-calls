## Open questions
1. **Block or label (for R3/I1; the request asks R1/I1 to decide and 05 to state it).** Options:
   - (a) Fail closed: a day strictly inside an interior gap > EARNINGS_GAP_WARN is EARNINGS_UNKNOWN (no sale). This matches 063's leading edge and the RI-002 root cause ("unknown stays unknown"). Cost: it blocks 4 sales that crossed no real report (findings 18-19).
   - (b) Label only: sell, but tag the trade (e.g. an `earnings_unknown` column in trades_*.csv) and count the tagged sales per stock. P&L would still include the calls held through the MO and MDLZ January 2022 reports. That is the "missing read as no earnings" outcome in RI-002, only made visible.
   - (c) Estimate the hidden date from cadence (e.g. last listed + one quarter). That is an estimate standing in for a value. In RI-002 occurrence 038, that kind of estimate was allowed only as the person's labelled house rule (040), so it would need the person's decision.
   R1 sees (a) as the only option that does not turn the unknown into a value. This is not a decision.
2. **One helper (request § Guardrail 3).** One formulation covers all three edges: find the listed dates bracketing d (a = last date ≤ d, b = first date ≥ d, e.g. with `bisect`). d is known iff both exist and `(b - a).days <= EARNINGS_GAP_WARN`. When d is itself a listed date, a == b and the gap is 0. Before the first date there is no a, and after the last date there is no b, so both edges are unknown. The interior check only has to look at d: if d ≤ a < expiry for a gap start a, the existing `_earnings_between` already gives EARNINGS_BLACKOUT. So "the call's life overlaps the gap" reduces to "d is strictly inside the gap". This keeps 063's fail-closed leading edge at any length, so it does not bring back the 120-day leading-edge bar that 063 rejected (063/01 Numbers). Whether the same 120 bar is right inside the data is the next question.
3. **Fixtures that will move (not a weakening).** The 3 controls at tests L219, L274 and L288 use a 220-day gap around the sale day (finding 5). They need a pair ≤ 120 d that still has no date in the call life, e.g. [2023-10-25, 2024-02-20] (Numbers). `REAL_BAC` (L455-481): BAC is not in the over-120 list, so its pins should not change (UNVERIFIED until I2 runs it). `_make` should be unaffected (finding 6, UNVERIFIED).
4. **Threshold inside the data.** 120 d works for the 5 US names (holes 175-184, normal ≤ 100). For ITUB, PBR and VALE, normal Q4 intervals of about 118-126 d sit near the bar (PBR 126 is flagged, VALE 120 is not). It does not change any report today (they are skipped), but it would if min_years or the quote history changed. Option: keep 120 and say so in the warning text.
5. **Counts and warning text.** The request asks for the effect to be "counted in the per-stock counts". `earnings_gaps_gt120` already exists. A new count (e.g. attempt days blocked inside gaps) and warning text like "... no call sold inside them (EARNINGS_UNKNOWN)" when `rule.skip_earnings` (as 063 did for the edge) are I1's design choice.
