- 3.3 `git commit <pathspec>` "will ignore changes staged in the index, and instead record the current content of the listed files"; `--only` is the default when paths are given; `-a` stages all modified known files. [https://git-scm.com/docs/git-commit] So any partial staging is undone if the commit names the log path or uses `-a`. The rule must say: plain `git commit` (no paths, no `-a`) after the helper, and no `git add logs/...` / `git add -A` after it.
- 3.4 `git add -p` "Interactively choose[s] hunks" and has no documented non-interactive mode, so agents cannot use it as the request suggests. [https://git-scm.com/docs/git-add]
- 3.5 Non-interactive ways to stage chosen content. (i) `git hash-object -w --stdin` writes a blob from stdin. With `--stdin`, filters are skipped unless `--path` is given, and `--path` applies the attribute filters of the named path. [https://git-scm.com/docs/git-hash-object] Then `git update-index --add --cacheinfo <mode>,<object>,<path>` inserts that blob into the index directly; `--add` is needed for a file not yet in the index (a new day's log). [https://git-scm.com/docs/git-update-index] (ii) `git apply --cached` applies a patch "to just the index, without touching the working tree". [https://git-scm.com/docs/git-apply] Option (i) needs no patch text and no context lines.
- 3.6 Content rule (design, from the file format; not from a doc): the staged blob is the working-tree file with the other items' uncommitted log lines dropped. Keep every line that is in HEAD's version, every non-log line (title, blank), and every `LOG_LINE` (scripts/check_pipeline.py L400) whose ID is the item's. Keep the working tree's order. Then, when the other item commits later with all its lines, the final blob equals the working-tree file. Staging "HEAD + own lines appended" would not: it reorders same-minute lines. `_item_lines` orders lines by (stamp, file index, line number) (L883-901, L946), so a reorder could move rule C's `start`. [repo file]
- 3.7 Missing-input rule (RI-002): if HEAD's lines are not an in-order subsequence of the working-tree file (a committed line was edited or removed), or the file is not UTF-8, the helper refuses with exit 2 and touches neither the index nor the file. It never stages the whole file as a fallback. [design; precedent in run-item.md L17 "a `--log` refusal (exit 2) goes back to the step"]
- 3.8 Where it lives: as a `check_pipeline.py --stage-log <ID>` mode it is a RULE_PATH (L363), so a change shows as RULES BRANCH, and each new `_git(` call must be added to `GIT_CENSUS` (test L2430-2432, now 47).
