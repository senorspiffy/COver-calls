## 3 ways FOR
1. **Use R1 option (a), but anchor the list it reads to something known, and do not parse pytest's summary line.** Membership is already safe in one direction: a kill passes only if its exact id is in the collected set, so a short or empty list can only cause false failures and never a silent pass. The remaining risk is a misleading failure message, and pytest's own source shows how the list can come back empty without any error. At verbosity below -1 (`-qq`), `_printcollecteditems` prints `"%s: %d" % (name, count)` per file instead of `item.nodeid` [https://pytest.org/latest/_modules/_pytest/terminal.html]. So one leaked extra `-q` (from `PYTEST_ADDOPTS`, for example) gives exit 0 and zero `::` lines. Recommended shape:
   - Build the child env by copying test_stale_bytecode.py's `STRIP` + `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` (L12-19).
   - Pass exactly one `-q`, `-p no:cacheprovider` and `--rootdir=<REPO>` (as test_stale_bytecode L24 does), with `cwd=REPO`. This makes the `tests/` prefix (R1 finding 2) deterministic.
   - `assert r.returncode == 0, r.stdout + r.stderr` (RI-002).
   - Keep only the lines that contain `::`.
   - Assert that `tests/test_pipeline_check.py::test_from_site_census` itself is in the set before checking any kill (a self-anchor). An empty or `-qq` listing then fails with a clear message.
   - Map each kill as `"tests/" + kill` in one place. This keeps all 33 SITE_ROWS strings unchanged (R1 open question 2) and gives the smallest diff.

   Reason not to parse "N tests collected": see AGAINST 1.
2. **Pin S7 in two layers: a no-git premise test that always runs, plus the differential test the request asks for, with a positive control.**
   - Layer 1 is R1 F(i). It asserts `log_fields_ok("I2", item, f, timed=True) == log_fields_ok("I2", item, f, timed=False)` for R1's four field shapes. It has no git and no subprocess, so it cannot be skipped. Parametrize `item` over a few IDs below TIMED_FROM ("076", "089") as well as one at "090", where the two must differ for the timed-valid field. The 090 row shows the test can tell the two calls apart.
   - Layer 2 is R1 F(ii) (`@NO_GIT`). It covers "identical output" from the request. It needs its own positive control: if both commands accidentally ran the real script, an identical-output test would pass without testing anything. Assert that the copy's text differs from the original in exactly one place (`count == 1` on `>= TIMED_FROM \`, R1 finding 22). Then run a second copy with a mutant that must change output (for example `>= TIMED_FROM + 1` at item "090" with the untimed-valid I2 line, where the real script enters the gate and the copy does not), and assert that its output differs. Without the control, "identical" proves nothing.
   - Then rewrite SITE_ROWS[6][4] as `EQUIVALENT (pinned by test_pipeline_check.py::<pin>[...]): ...` and let the census resolve that id like any kill (R1 F, census link). Renaming the pin then fails the census.

   The French source says equivalence detection is undecidable in general, but "certaines méthodes d'analyse de code permettent d'en repérer certains" [https://www.lri.fr/~longuet/Enseignements/16-17/L3-GLA/L3-TestMutations.pdf]. Layer 1 pins exactly that code-analysis premise. Layer 2 gives the behaviour sample the request asks for.

## 3 ways AGAINST
1. **The child collection costs time on every run and depends on pytest's text output, and pytest is not pinned.**
   - Time: R1's upper bound is 4.11 s per collection, about 3% of a two-file run (R1 Numbers). It applies to every full suite and to every mutant run in a 109-style mutation pass (34 runs). The real time is UNVERIFIED.
   - Output format: the format is pytest's, not ours, and `dev = ["pytest"]` is unpinned (pyproject L13). Outside tools that parsed `--collect-only` output have broken on summary-line variants. One PR notes the real line includes "a `collected / total` pair and a `(N deselected)` clause" [https://github.com/rtk-ai/rtk/pull/925].
   - Mitigation: parse only `::` lines, never the summary (FOR 1), and keep the self-anchor. Option (b') (ast `ids=` plus importing `FROM_IDS`) costs about 0 s. But it rebuilds pytest's id rules by hand and would miss dedupe suffixes and stacked joins (R1 findings 5-6). Keep (a), but I2 must measure the added seconds and record them in 05.
2. **The differential S7 test is a sample, not a proof. It can skip without git and it is tied to the exact source text, so it may cost more than it pins.**
   - Sample, not proof: by the French source, detecting equivalent mutants is a "problème indécidable" [https://www.lri.fr/~longuet/Enseignements/16-17/L3-GLA/L3-TestMutations.pdf]. Two inputs at 089 show identical output for those two inputs only.
   - Practitioner view: the Russian source says there is no universal fix ("Универсального решения нет") and suggests a registry that mutes such mutants [https://habr.com/ru/post/462709]. That is closer to 109's SITE_ROWS EQUIVALENT row than to a behaviour test.
   - Skip and cost: `@NO_GIT` means the pin can be silently absent (109 02 AGAINST 2), and it adds two or three git fixture runs.
   - Source coupling: the string replace on `>= TIMED_FROM \` ties the test to the formatting of L1089. Any reformat must break it loudly (`count == 1`), and that is maintenance.

   Hence FOR 2: Layer 1 is the real pin and is always run. Layer 2 is there because the request says "identical output". If R3 judges Layer 2 too costly, Layer 1 plus the census link still meets "S7 equivalence has a named test".
3. **Exact matching adds failure modes unrelated to cutoffs, and the cheap in-process shortcuts are unsafe.**
   - Failures unrelated to cutoffs: a collection error in either file, or a new module-level skip, now also fails the census. So one break shows up as two failures. A future param id with non-ASCII characters or a duplicate is changed by pytest (R1 findings 5 and 7), so the kill must be written in its final collected form.
   - Why in-process is tempting: Chinese write-ups suggest an in-process plugin that stores ids from `pytest_collection_modifyitems` and is driven via `pytest.main` [https://www.cnblogs.com/superhin/p/pytest-collect-tests.html]. That looks free.
   - Why it breaks: pytest warns against repeated in-process `pytest.main` (R1 finding 11). Also, `-k` selects by substring of the name (Turkish and Spanish tutorials below), and a node-id run collects only that node. A census that reads the parent's own items would therefore see a partial list under `pytest -k census` or `pytest tests/test_pipeline_check.py::test_from_site_census`. If someone then "fixes" that by skipping when the list looks incomplete, it becomes a silent pass (RI-002).
   - Rule: the census must collect in its own child, every time, and never read the parent session. R1 option (d) is rejected for this reason.

## Holes to watch out for (summary)
- `-qq` or a leaked `-q` in `PYTEST_ADDOPTS`: the listing becomes `file: count` lines with exit 0. Strip the env (copy test_stale_bytecode `STRIP`) and self-anchor on the census's own nodeid.
- Do not parse the "N tests collected" summary line. Its form varies (`collected / total`, `(N deselected)`). Keep only `::` lines.
- The child exit code must be exactly 0, or the census fails and prints stdout and stderr (RI-002). Whether a collection error gives exit 2 is UNVERIFIED and does not matter if the check is `== 0`.
- Pass `--rootdir=<REPO>` and `cwd=REPO` so the `tests/` prefix is fixed. Map kills with `"tests/" + kill` in one place rather than editing 33 strings.
- Never read the parent session's items, and never use in-process `pytest.main`: `-k census` and node-id runs give a partial list. If a partial list is "handled" by skipping, it becomes a silent pass.
- The negative tests (RI-012) should cover: misspelled param id (`TIMED-FROM-l`), param id dropped from a parametrized test (R1 finding 17, which the current check misses), and a bracket added to a plain test. Feed them to a pure helper `_unresolved(kills, collected)` with a fixed collected set, so the negative tests need no subprocess.
- S7 differential: put the mutant copy in its own tmp dir, never at the fixture repo's `scripts/check_pipeline.py`. `_timed_repo` writes RULE_FILE text there (tests L4544) and commits it, so overwriting it would change what `_rule_seen` reads. The script is cwd-based (check_pipeline.py L1627, L1863), so a copy run with `cwd=<fixture repo>` reads the fixture.
- S7 differential needs a positive control (a must-differ mutant) and `count == 1` on the replaced text. Otherwise "identical output" can pass without testing anything.
- S7 Layer 1 must include a row at "090" where timed and untimed differ, so the premise test is shown to tell the two calls apart.
- S7 at 089 is a new fixture ID for `_timed_repo` (R1 finding 21; RI-001, A1 follow-up 4). I1/I2 must run it once before FIT.
- Alias check: use node identity (`id(node)`) for "inside a Compare", not line numbers. Exclude UNTRACKED_FROM and Store ctx. Expect false alarms on any local name ending `_FROM`, and treat them as findings to rename, not to allowlist silently.
- Census link: if SITE_ROWS[6][4] gains `(pinned by ...)`, update the census's own EQUIVALENT assert (L6171) and its `startswith("EQUIVALENT")` filter together. The prefix changes from `EQUIVALENT:` to `EQUIVALENT (`.
- Measure: I2 must record the added seconds of the child collection in 05. The 4.11 s figure is only an upper bound (R1 Numbers).
