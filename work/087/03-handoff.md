## Decisions on R1/R2 open points (with reasons)
- **D1 Properties and aliases (R1 OQ1, R2 FOR 1): fail closed.** A value that starts with `&`, `!` or `*` is an error. This needs none of the anchor/tag/alias sub-grammar (#18, #19). It costs 0 real lines (#7) and covers a property alone on its line (q14) and on `tools:` itself (q20, which wins over `_field`'s text). The rule is anchored at the value start (RI-012, #8).
- **D2 Flow collections (R1 OQ2, R2 AGAINST 1 and 3): a `[` or `{` at a value start must close on its own line.** It is read by a single-line, quote- and comment-aware bracket scanner with a closer stack. After the close, the rest must full-match the existing AFTER_CLOSE_RE. This is the request's "open `[`/`{` on any key is an error", and the docs' mcpServers `args: [...]` still passes (q23). Lines starting `tools:` or `disallowedTools:` at column 0 are exempt, because `_field` already reads them and errors on any open or unreadable form (L73-L76, ENTRY_RE). So g, h, j3, m, v and n1 keep their results. Multi-line flow is never parsed (080 AGAINST 2). Known fail-closed false error: an apostrophe or quote inside a plain scalar inside a flow collection (`[it's]`), because the scanner treats it as a quote start.
- **D3 Other value-start indicators (R1 OQ3, F24-F25; R2 Hole 6): `?` and `:` at a value start are errors too, with the same text as D1.** The key group can no longer start with `&`, `!`, `*`, `[`, `{`, `?` or `:`. Without this, `  - {a: b,` reads `{a:` as a key and hides the open brace (q15, M33). It costs 0 real lines, since every real key starts with a letter (#7). The allow-list (R2 AGAINST 2) is not adopted. It is a larger rewrite, and D1-D4 cover every shape found so far with named fixtures.
- **D4 Tabs after an indicator, and p11 (R1 OQ4, R2 FOR 3): fail closed (option a).** A tab anywhere before the value start (after `-`, inside or after `key:`) is an error. `(?:-[ ]+)*` becomes `(?:-[ \t]+)*` so that `-\t` is part of the prefix. p11 flips to an error. No runtime claim is made (080 D8), and `claude plugin validate` is not needed.
- **D5 Precedence within a line:** (a) a tab in the leading whitespace (080, unchanged); (b) a tab before the value start; (c) the value-start character: `&!*?:` → D1 text; a quote → the 080 quote rule (unchanged); `[`/`{` on a non-exempt line → D2. The first error in file order wins (080 D1). `n = i + 2` is unchanged.
- **D6 Docstring (R1 OQ5):** add an "Item 087" paragraph naming the new unreadable cases and the known fail-closed false errors (anchors, tags and aliases, explicit `?`/`:` keys, tabs after an indicator, quotes inside flow plain scalars, valid multi-line flow). Keep "This says nothing about what Claude Code does".
