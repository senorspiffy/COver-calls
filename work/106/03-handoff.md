## Decisions
- D1 (R1 OQ1, R2 FOR 2): rule B, widened to every path in row 6. A tab on a frontmatter line that is not blank, not a comment and not block content is an error, with two exceptions: inside the quoted scalar that starts the value, or after the first ` #` (a space, then `#`) that follows that quote or flow collection. The basis is the spec (tabs are separation white space, rows 17-18), the measured split between loaders (rows 4, 46, 71) and RI-002 (the runtime parser is unknown, row 24). So the shape counts as unreadable and fails closed. The error text names the item: `TAB_PLAIN = "tab outside quotes and comments on frontmatter line {} (item 106)"`. The docstring lists the spec-valid tab shapes as known fail-closed false errors. It says "the loaders disagree (measured on PyYAML 6.0.1/6.0.4)", not "PyYAML rejects it" (row 67).
- D2 (R1 OQ2): a tab inside a key is covered by D1 (w10). No separate rule.
- D3 (R1 OQ3): `  a: v` / `  - x` (an indented sequence after a scalar-valued key at the same indent) is not checked, and the docstring lists it under "Not checked". It is outside the request, and step 2 protects the tools path.
- D4 (R1 OQ4, R2 AGAINST 2): s5 is refused. If I2's probe shows that PyYAML loads s5, 05 lists it as a known fail-closed false error (no code change). If PyYAML raises on s3, s6 or s7 (all expected to pass), 05 records it and the docstring lists that shape under "Not checked". This is not a Deviation.
- D5 (R1 OQ5, R2 FOR 1): handled here, in `_field` (step 2). The docstring keeps "a continuation that starts with `- `" only for keys other than `tools:`/`disallowedTools:`.
- D6 (S-3, R2 FOR 3): `in_flow` is set on a FLOW_KEYS line and cleared by `_ends_field`, which `_field` also uses. While it is set, the continuation branch leaves the line to `_field`.
- D7 error texts: `INDENT = "indent matches no open level on frontmatter line {} (item 106)"`; in `_field`, `f"{key}: list items at different indents (item 106)"`. `n` is the test's own count (`i + 2`), never PyYAML's mark.
- D8 fixture ids: R2's `t1`/`t2` become `tb1`-`tb3`, so they cannot be confused with the existing `t1_unbalanced`/`t2_two_parens`.
