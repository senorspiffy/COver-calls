- **F1 BUG (RI-002 near miss, caught before merge, not counted, precedent 069/070/075): an anchor or tag before an open quote still lets an absorbed `tools:` line pass.**
  - Evidence, on the real r1 file in the worktree: `description: &d "Research team, ...` / `tools: Read, Write, Glob, Grep, WebSearch, WebFetch` / `end"` gives `59 passed`. The same with `!!str "` gives `59 passed`. PyYAML reads both as keys `['name', 'description']` with `tools` None, which is the 075 P1 outcome (inherits every tool if the runtime reads it the same way; runtime UNVERIFIED).
  - `shapes.py` gives the same result for `!!str '...`, `&a !!str "...` and `- &a "...` (test `{'Read', 'Write'}`, PyYAML no `tools` key).
  - 01 F10 ("anchor, tag ... fail closed") only covers an anchor or tag on the `tools:` value itself.
  - Root cause: QUOTE_START_RE expects the quote directly after `key: ` or `- `. YAML allows node properties (`&anchor`, `!tag`) between the indicator and a quoted scalar, and the rule was written from the two probe shapes rather than from the grammar of what can come before a scalar.
  - Guardrail: allow an optional `(?:[&!][^\s]*[ \t]+)*` before the quote group in QUOTE_START_RE. Or, simpler and fail closed: any frontmatter value starting with `&`, `!` or `*` is an error. Add fixtures for anchor, tag, anchor+tag and `- &a "`, at both parser and tree level, plus a mutation that removes the properties part.
